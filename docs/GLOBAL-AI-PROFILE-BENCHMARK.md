## Adapted profile strategy

1. SEO audit: current metadata is a foundation; the next gap is project depth and evidence.
2. Addressable search market: separate branded/navigational, engineering/informational and hiring/commercial terms; do not invent volumes.
3. Intent: name searches need identity, work and contact. Hiring searches need capability, source proof and availability.
4. Reusable case-study structure: problem, architecture, source evidence, limitations and next measurement.
5. Entity clarity: one public name and shared Person identity across specialist sites.
6. Topic clusters: agents/tool integration, LLM applications, developer tools and end-to-end AI product delivery.
7. Competitor differentiation: enterprise software foundation plus public developer tools; replace generic lists with reviewable work.
8. Buyer topics: scoped AI app builds, MCP integration, AI feature integration, CLI tooling, SaaS MVP delivery. Avoid fake comparison/review pages.
9. AI-readable content: direct summaries, accurate project links and explicit scope; no guarantee of inclusion in AI answers.
10. Overlooked demand: developer workflows with approvals; AI apps that work without credentials; local-first AI UX; typed agent state; troubleshooting provider failures. These are topic hypotheses, not measured zero-volume keywords.

## Measurement roadmap

For QuizFlow: structured-output validity, failure rates, response latency, model cost per generated quiz and behavior when credentials are absent.
For Vibe: success per tool, failed-tool recovery, approval-path behavior, context handling and task latency.
For LangGraph: graph contract tests, recovery/checkpoint behavior and an evaluated execution layer before claiming autonomous delivery.
Publish baselines, dataset sizes, measurement dates and reproducible commands before displaying metric badges.
